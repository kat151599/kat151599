ServiceHub

One desktop console to launch, monitor, and diagnose local processes, containers, and remote Windows services—rather than managing separate scripts, logs, and status windows.

The problem

Managing several independent Windows applications on one computer creates operational overhead: different launch commands, fragmented logs, no consolidated availability status, and the risk of accidentally starting duplicate instances.

The solution

ServiceHub consolidates application lifecycle operations into one local desktop console. One application equals one visible service card, with its status, startup policy, event history and health checks. The service manager itself must operate even when no managed projects exist.

Implemented in the desktop source

  • Control of Windows processes (EXE, BAT, CMD), Docker containers and Docker Compose stacks.
  • HTTP/TCP checks and WebSocket heartbeats; monitoring-only services are not exposed to start/stop commands.
  • Local SQLite, event logs, statuses, basic restart-on-failure behavior.
  • Discovery of potential launch sources in a project directory with exclusions for virtual environments and generated files.
  • Remote Nodes v1 and token-authenticated API modules exist in the source; some live remote workflows still need end-to-end acceptance.

Technical approach

Python · PySide6 / Qt · SQLite · psutil · WebSocket · HTTP/TCP health probes · Docker API / CLI · Windows process identity. Development follows a source-first branch with guarded changes and real-environment verification.

Demo and validation

The public Demo Edition provides five sections: Overview, Services, Logs, Statistics and Settings. It starts with eleven fictional service records and also supports a completely empty dataset. User changes and events remain in browser-local storage.

The sandbox demonstrates start, stop, restart, CRUD, search, a synthetic remote node, and reset. Passing browser demo tests should not be confused with full acceptance of every feature in the native Windows application.

Scope and privacy

This is not the unchanged PySide6 binary streamed to a browser. It is an independent, isolated reconstruction with no connection to live ServiceHub systems, private service configuration or secrets. The desktop source repository remains private.
