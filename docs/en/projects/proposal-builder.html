PROJECT CASE STUDY / Document automation

Proposal Builder System

Replace repeated calculations and manual proposal assembly with a controlled workflow from customer data to a finished HTML document.

Working internal toolPortfolio case study

The problem

Managers had to move customer data, equipment configurations, financial figures and document layouts through repetitive manual steps, increasing the chance of inconsistent values.

The solution

A web application separates structured inputs, the calculation engine and reusable HTML designs. Proposal data does not depend on how the final document looks.

Implemented features

  • Required-field validation and automatic technical/financial calculations.
  • Custom HTML templates driven by stable field codes.
  • Drafts, editing, copying and document history.
  • Recalculation of derived values when a saved proposal is reopened.

Technical approach

Python · Flask · Waitress · JavaScript · HTML templates · REST-style API. The core design separates input data, calculation rules and presentation, with distinct create/update paths for drafts.

Demonstration & validation

The public case documents validation and the edit, copy and recalculate workflows. An actual interactive Demo Edition—not a static screenshot—is embedded above. You can change fictional inputs, recalculate results and produce HTML. The demo is also available in full size via the button above.

Scope & privacy

The public demo uses fictional data and runs in the visitor’s browser. Production customer data, private settings and credentials are not published. No unverified time-saving metrics are claimed.
