The problem

Leads and calls should not remain disconnected from client records and tasks. Otherwise teams lose the original contact source and earlier conversations when an inquiry becomes a project.

The solution

An existing task-management platform was extended with CRM capabilities and an integrated Call Center. Leads have provenance, an ingest method and an event log. Conversion creates a client project with linked historical context.

Implemented features

  • Client CRM profiles with contacts, addresses, status, owners and custom fields.
  • Unified client timeline covering notes, calls, meetings, task events and updates.
  • Call Center workflows for leads, provenance, call logs and status changes.
  • Lead-to-client history continuity design with safe retry semantics.

Technical approach

The working platform is built by extending open-source Vikunja (Go/Vue) with an integrated Call Center component. This is a customization and integration project, not a claim to have authored Vikunja itself.

Demonstration & validation

The standalone sandbox above illustrates a fictional lead progressing through contact, qualification and conversion. A simulated repeat submission creates no second record. It has no API, telephony or production database connectivity.

Scope, attribution & privacy

No production source, customer records, credentials or server configuration are published. ClientCircuit is a separate portfolio-only name and original visual identity. Technical origins: Vikunja and a Call Center component adapted from Open Cold Dialer; upstream licenses remain applicable. External website intake is documented separately and not claimed here as a completed production integration.
