ServiceHub

Одна панель для запуску, нагляду й діагностики локальних процесів, контейнерів і віддалених сервісів Windows — замість набору розрізнених вікон і скриптів.

Windows · Python · PySide6Source-first · активна розробкаІнтерактивна Demo Edition
01Справжній настільний застосунок

Основний ServiceHub написаний на Python / PySide6 і працює у Windows.

02Окремий інтерактивний стенд

Браузерна реконструкція відтворює головні сценарії з синтетичними даними.

03Жодного доступу до сервера

Немає команд ОС, Docker, токенів, виробничої SQLite або мережевих підключень.

Проблема

Коли на одному Windows-комп’ютері працюють кілька незалежних застосунків, керувати кожним вручну незручно: окремі команди запуску, різні журнали, відсутність єдиного індикатора доступності й ризик запустити другий екземпляр.

Рішення

ServiceHub об'єднує життєвий цикл застосунків у локальній панелі керування. Один застосунок — одна видима картка з власним станом, правилами автозапуску, журналом і перевірками доступності. Керований сервіс не має бути залежністю самого диспетчера.

Реалізовано в настільних вихідних кодах

  • Керування Windows-процесами (EXE, BAT, CMD), а також Docker і Docker Compose.
  • Нагляд через HTTP/TCP та WebSocket heartbeat; відокремлення моніторингу від команд керування.
  • Локальна SQLite, журнали подій і логів, статуси, базове відновлення після збоїв.
  • Пошук кандидатів запуску у папці проєкту з фільтрацією віртуальних середовищ і службових файлів.
  • Модулі Remote Nodes v1 з token-authenticated API. Окремі віддалені сценарії ще потребують повної live-перевірки.

Технічний підхід

Python · PySide6 / Qt · SQLite · psutil · WebSocket · HTTP/TCP health probes · Docker API / CLI · Windows process identity. Робочі вихідні коди розвиваються окремою source-first гілкою, з контрольованими змінами та тестуванням реального середовища.

Демонстрація та перевірка

Публічна Demo Edition показує п’ять основних розділів: Огляд, Сервіси, Логи, Статистика, Налаштування. Працює з одинадцятьма вигаданими записами або абсолютно порожньою базою. Додані/змінені записи та журнал залишаються в локальному сховищі браузера.

Відтворено запуск, зупинку, перезапуск, CRUD, фільтрацію, тестовий віддалений вузол та скидання даних. Перевірені сценарії браузерної демоверсії не слід плутати з повною приймальною перевіркою кожного модуля нативної програми.

Обмеження й приватність

Це не веб-порт реального PySide6-бінарника: для безпеки він не підключається до локального або віддаленого ServiceHub. Немає доступу до робочих сервісів чи конфіденційної конфігурації. Репозиторій нативного інструмента залишається приватним.
